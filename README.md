**Дисциплина:** Базы данных  
**Выполнил:** Кораблёв Кирилл  
**Вариант:** 25  
**СУБД:** PostgreSQL

## Цель работы

Создать реляционную базу данных по заданному варианту, определить структуру таблиц, установить ограничения целостности и заполнить таблицы исходными данными.

## Предметная область

**Учёт почтовой корреспонденции.** База данных хранит сведения о видах почтовых отправлений, допустимых весе и габаритах, а также о конкретных отправлениях.

## Структура базы данных

Используется схема `korablev25`, содержащая две связанные таблицы.

### `correspondence_types` — виды корреспонденции

| Поле | Назначение |
| --- | --- |
| `type_id` | Идентификатор вида корреспонденции, первичный ключ |
| `type_name` | Наименование вида |
| `packaging` | Тип упаковки |
| `min_weight`, `max_weight` | Допустимые границы веса |
| `min_length`, `max_length` | Допустимые границы длины |
| `min_width`, `max_width` | Допустимые границы ширины |
| `min_height`, `max_height` | Допустимые границы высоты |

### `correspondence` — почтовые отправления

| Поле | Назначение |
| --- | --- |
| `track_number` | Трек-номер, первичный ключ |
| `type_id` | Идентификатор вида, внешний ключ |
| `weight_grams` | Вес отправления в граммах |
| `length_cm`, `width_cm`, `height_cm` | Габариты в сантиметрах |
| `sender_code` | Код отправителя |
| `stamps_amount` | Стоимость марок |

**Связь:** `correspondence.type_id → correspondence_types.type_id` (один ко многим). При изменении и удалении записи родительской таблицы предусмотрены `ON UPDATE CASCADE` и `ON DELETE CASCADE`.

## Состав файлов

| Файл | Описание |
| --- | --- |
| `01_lab1_variant25.sql` | Создание схемы, таблиц, ограничений и заполнение данными |
| `correspondence_types.csv` | Данные таблицы видов корреспонденции — 10 записей |
| `correspondence.csv` | Данные таблицы отправлений — 24 записи |

CSV-файлы содержат заголовки столбцов и разделены запятыми; кодировка — UTF-8 с BOM. Данные соответствуют записям `INSERT` первой лабораторной работы. В отдельных трек-номерах намеренно сохранены пробелы, а `type_id` одного отправления имеет значение `NULL` — эти данные используются в следующих работах.

## Порядок выполнения

1. Создать базу данных PostgreSQL `kirill_korablev_25` (при необходимости — с помощью отдельного скрипта `00_create_database.sql`).
2. Подключиться к созданной базе данных.
3. Выполнить файл `01_lab1_variant25.sql` в редакторе SQL.
4. Убедиться, что в схеме `korablev25` созданы таблицы `correspondence_types` и `correspondence`.
5. Проверить число записей запросом ниже.

```sql
SELECT 'correspondence_types' AS table_name, COUNT(*) AS row_count
FROM korablev25.correspondence_types
UNION ALL
SELECT 'correspondence', COUNT(*)
FROM korablev25.correspondence;
```

Ожидаемый результат:

| table_name | row_count |
| --- | ---: |
| `correspondence_types` | 10 |
| `correspondence` | 24 |

## Реализованные ограничения

- `PRIMARY KEY` обеспечивает уникальность идентификаторов и трек-номеров.
- `FOREIGN KEY` обеспечивает ссылочную целостность между таблицами.
- `NOT NULL` запрещает отсутствие значений в обязательных полях.
- `CHECK` проверяет положительность веса и размеров, а также допустимость заданных границ.
- `ON UPDATE CASCADE` и `ON DELETE CASCADE` задают каскадное поведение внешнего ключа.
